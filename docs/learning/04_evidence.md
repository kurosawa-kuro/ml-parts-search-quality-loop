# いま証跡が答えていること

通し実行の数字は [Golden Path 通し検証](../tasks/05_done/2026-09-22-GoldenPath通し検証とAC証跡.md) が出典である。
ここに写すのは学習上の読み方だけで、新しい測定値は足さない。

## 観測されたこと

1,500 SKU / 700 family / 1,400 クエリで、ベクトル検索のあとに構造化特徴と LambdaRank を足した。

- Recall@100 の差は 0。候補に入る集合は、順位学習では変わっていない
- NDCG@10 は baseline 0.7479 から、3 seed とも +0.2429
- 検索成功率は 0.757 から 0.971
- 誤適合率は 0.243 から 0.029
- 再検索率は 0.227 から 0.171
- 失敗の内訳は retrieval_miss 488、rerank_miss 336、simulation_miss 4

読み方: 検索の取りこぼしは残ったまま、**候補の中の順位、とくに 1 位の適合**が動いた。
オフライン（NDCG）とオンライン（成功率、誤適合）が同じ方向に動いた一例である。
元メモの教材（寸法が近い別部品が 1 位に来る）に対して、構造化特徴が効いた、という読みと整合する。

10,000 SKU / 正解 2,000 万行の別実行も exit 0 / promote で、holdout の NDCG@10 は +0.2589、検索成功率の差は +0.21、誤適合率の差は -0.21 だった。同じ方向である。

seed 三つで NDCG が小数 9 桁まで同じだった。モデルの checksum は seed ごとに違う。
点数の一致は頑健性ではなく、トレーナーが seed を使っていないことの表示である。

## 観測されていないこと

このプロジェクトが学習対象にしているのは、**食い違ったあと、オンラインだけを戻す 2 周目**である。
その証跡はまだない。

残っていないもの:

- NDCG は上がったのに検索成功率が動かない、という実行を保存し、不採用にした記録
- その失敗 ID だけを入力に、特徴か検索のどちらか一方を変えた次の実験
- 2 周目で、holdout と production のオンライン点数が学習集合と同じ方向に動いた記録
- オフライン指標がオンライン KPI を予測し損ねた頻度。予測器として使えるかは、両方が一緒に動いた一例では分からない

合格条件は、食い違いを `promote` にしないところまでは実装されている。
不採用のあとオンラインを上げた、という学習の本題は、これからこの土台で行う実験である。

## 学習として次にやること

新しいモデルを足す前に、今の成果物で次を自分の言葉で説明できることを目標にする。

1. Recall が動かず NDCG と検索成功率が動いたのは、どの失敗種別が減ったからと読めるか
2. `simulation_miss` が 4 件残ったとき、採用してよかった判断はどの関門が支えているか
3. もし検索成功率だけが baseline 以下だったら、どのファイルを見て、どの category の実験を開くか

3 が口頭で辿れれば、食い違いの実験を回す準備ができている。
その実験を回すまでは、オンライン精度の手順を体得したとは扱わない。
