# 01 要件

> 最終更新: 2026-09-21。PoCの要求を定義する正本。実装済みを意味しない。構成・実現方法は [02_architecture.md](./02_architecture.md)、検討素材は [元設計メモ](./archive/search-quality-loop-brainstorm.md) を参照。

## 目的

多言語の部品検索で、失敗検知 → 正解データ（Ground Truth、GT）更新 → 改善・再学習 → 独立評価 → 疑似オンライン検証を繰り返し、検索品質を継続的に改善する仕組みを再現可能なPoCとして示す。

オフライン指標の向上だけで完了とせず、疑似オンライン分布でも検索成功率・誤適合・再検索などの変化を確認する。シミュレーションの結果から実サービスでの効果を実証したとは扱わない。

## 範囲

対象:

- 架空の商品カタログ（10,000〜50,000 SKU）、多言語クエリ、GTの生成。
- 型番・寸法・材質・規格・用途など、意味的類似だけでは満たせない検索条件。
- 検索候補取得、構造化属性を使うランキング、改善前後の比較。
- オフライン評価、言語・クエリ種別などのSlice分析、失敗原因の抽出。
- 疑似オンラインイベントから失敗を検知し、GT・特徴量・ランキング改善へ戻すループ。
- 学習・調整用、Holdout、本番相当のシミュレーション用データを分離した検証。
- 実験ごとの設定・データ・GT・モデル・評価結果の対応を追跡すること。

非対象:

- 実案件の商品・顧客・検索ログの利用。
- 実商用サービスへのデプロイ、実トラフィックを使うA/Bテスト。
- ECの購入・決済・在庫管理機能そのもの。
- 大規模な検索品質管理UIや汎用プラットフォームの構築。

## ユーザー

一次ユーザーは、部品検索の品質改善を担当するML / 検索エンジニア。失敗原因を切り分け、改善候補の効果と回帰を判断する。PoCのレビュー担当者は、同じ実験条件と成果物から判断根拠を確認する。

## ユースケース

| ID | ユースケース | 成功条件 |
|---|---|---|
| UC-001 | 評価用データを準備する | カタログ・クエリ・GTと分割条件を識別できる |
| UC-002 | Baselineを評価する | 検索結果と指標をクエリ単位で追跡できる |
| UC-003 | 失敗を分析する | 言語・クエリ種別・カテゴリ等のSliceから失敗例と原因を確認できる |
| UC-004 | GT・検索処理・特徴量・ランキングを改善する | 変更内容を実験として記録し、比較対象を特定できる |
| UC-005 | 改善候補を独立評価する | Holdoutと疑似オンライン分布で改善・回帰を確認できる |
| UC-006 | 次の改善に戻す | 疑似オンラインの失敗から次のGT更新・改善実験へつながる |

## Critical User Journey / Golden Path

一次ユーザーが、Baselineの失敗を根拠に改善を行い、独立したデータで結果を確認して次の実験へ戻る一本道を中核とする。

| # | ステップ | 成功条件（観測可能な状態） |
|---|---|---|
| 1 | データ・クエリ・GTと実験条件を準備する | データ版・GT版・分割条件・seedを参照できる |
| 2 | Baseline検索を実行・評価する | 順位付き結果、全体指標、Slice指標が得られる |
| 3 | 疑似オンラインイベントと評価結果から失敗を抽出する | 失敗Queryと寸法違い・適合違い等の根拠が得られる |
| 4 | GT・特徴量等を更新し再学習する | 変更点・学習入力・新モデルを追跡できる |
| 5 | Holdout・本番相当分布で比較する | 同じ比較条件で改善量と回帰Sliceが分かる |
| 6 | 採否を記録し、次の疑似オンライン実験へ戻す | 採用または保留の根拠と次の実験の関係を確認できる |

完了状態は、単発評価ではなくこのループを少なくとも1周実行し、改善前後の証跡を提示できること。構成要素への対応は [基礎設計](./02_architecture.md) に定義する。

## 評価と受入条件

| ID | 観点 | 要求・受入条件 |
|---|---|---|
| AC-001 | 再現性 | 実験設定、各データ版、モデル版、seedと評価結果を対応づけられる |
| AC-002 | オフライン | Recall@100 / NDCG@10 / MRR@100を改善前後で比較できる |
| AC-003 | Slice | 言語・Query Typeを必須軸とし、カテゴリ・型番・自然文・寸法依存等の失敗を切り分けられる |
| AC-004 | 疑似オンライン | Search Success Rate / CTR / Zero Result Rate / Reformulation Rate / Conversionを比較できる |
| AC-005 | データ分離 | Training / tuning、Holdout、Production-like simulationを分離し、異なるseedと分割根拠を記録する |
| AC-006 | 失敗改善 | 寸法違いまたは適合違いの失敗例から改善し、独立評価でも結果を確認できる |
| AC-007 | 継続性 | Golden Pathを1周し、失敗・変更・実験・評価・次の判断を関連づけられる |
| AC-008 | 評価の完全性 | 正常0件・実行失敗・未実行・GT未判定を区別し、不完全な比較を合格扱いしない |
| AC-009 | 学習の整合性 | 学習と推論の特徴量定義が対応し、ラベル・未来情報の混入を検出できる |
| AC-010 | 可逆性 | 疑似オンラインに使った構成を特定でき、切替失敗時に直前の検証済み構成へ戻せる |
| AC-011 | 比較可能性 | 同じ評価母集合・GT・指標定義で比較し、Sliceの件数と除外理由を報告できる |

元メモのNDCG 0.61→0.83等は架空の到達例であり合格閾値ではない。指標・GT・分母の契約は [05 データモデル](./05_data_model.md)、採否ゲートと検証方法は [07 テスト戦略](./07_test_strategy.md) を正本とする。許容回帰・最小改善量・最低Slice件数は実験前に確定し、未設定のまま合格判定しない。

実物の参照コードを踏まえ、再現性はseedだけでなく入力集合・判定・特徴量・実行環境まで追跡する。参照先の挙動と本PoCの採否判断は [レビュー](./reference-implementation-review.md) に分離して記録した。

## 制約と未決事項

- 実データをコピーせず、検索問題の構造を架空データで再現する。
- 初期設定はFA部品総合EC。自動車部品は将来候補とし、両方の実装は必須にしない。
- 初期対応はJA / EN。DE / ZHは将来候補。初期SKU数・family数・分割比率は05のローカル初期設定を参照する。
- GT・分割の共通契約は05に従う。商材固有の属性・許容差とsimulation確率は実装前に決める。
- 本文はPoCの要求を整理したもので、プロダクトのテスト・動作はまだ検証されていない。
