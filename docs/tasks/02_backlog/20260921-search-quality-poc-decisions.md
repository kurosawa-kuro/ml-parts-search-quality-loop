# 検索品質PoCの未決事項を確定する

## Goal

実装に必要な選択と評価契約を決め、[要件](../../01_requirements.md)・[基礎設計](../../02_architecture.md)へ反映する。

## Context

素材は [設計メモ](../../検索品質-継続改善ループ-PoC設計メモ.md) から参照。推奨・候補を確定事項と混同しない。

## 判断項目

| 項目 | 候補・論点 | 決定時期 |
|---|---|---|
| 商材 | FA部品総合EC（推奨） / 自動車部品 | データ生成前 |
| 規模・言語 | 10,000〜50,000 SKU内の初期規模、JA / EN / DE / ZHの採否・配分 | データ生成前 |
| データ契約 | 商品・クエリID、単位、欠損、正規化、翻訳対応、保存形式 | データ生成前 |
| GT | 条件競合・不適合・欠損、ラベル名称、判定根拠 | GT生成前 |
| 分割 | 分割単位、派生・翻訳の重複防止、seed、Holdout再利用方針 | 学習・評価前 |
| Retrieval | Qdrant / pgvector / FAISS、Embeddingモデル、構造化filter / boost | Retrieval実装前 |
| 拡張検索 | BM25 / Hybrid / RRFの採否・追加順 | Baseline構築時 |
| 指標 | relevant閾値、NDCG gain、MRR対象順位、KPI分母・成功条件、未判定データの扱い | 評価実装前 |
| 品質ゲート | 主指標、改善量、許容回帰、Slice件数不足の扱い | 改善実験前 |
| イベント | 検索結果との結合、時刻、欠落・重複、行動シミュレーション、暗黙判定のGT反映 | Feedback実装前 |
| Experiment | 入力版、実行環境、モデル・設定・結果の保存形式、IDとCLI | 実験実装前 |
| GT更新後の比較 | 共通GTでの再評価、旧版保持、実験間比較条件 | 改善実験前 |
| OSS参照 | 現在の機能・適用範囲・ライセンス確認、コード流用の要否 | 依存導入・流用前 |

## Acceptance Criteria

- 採否と理由を記録し、確定事項を01/02へ反映する。
- 実装に必要な項目から順に判断し、未決のままの部分は採用済みと扱わない。
