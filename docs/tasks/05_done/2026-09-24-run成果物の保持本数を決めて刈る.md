# 成果物 run の保持本数を決めて刈る

Weight Class: Light

## Goal

`artifacts/<group>/<run_id>/` が実行のたびに増え続ける状態をやめる。保持本数を
設定で宣言し、それを超えた古い run を明示的なコマンドで削除できるようにする。

## Value

2026-09-24 に `artifacts/` が 4.5 GiB へ育ち、ディスク不足で `publish_run` が失敗して
Golden Path が止まった。GT の gzip 化（判断日誌 2026-09-24）で 1 run あたりは
約 68 MB まで落ちたが、**増え続けること自体は直っていない**。1 回の pipeline で
9 段階ぶんの run が生まれるため、放置すれば同じ止まり方を繰り返す。

## Scope

- `env/config.yaml` に保持本数（group ごと、または共通の既定値）を追加する。
- `parts-search prune`（仮）で、保持本数を超えた古い run を削除する。
- `artifacts/active.json` が指す release と、その release が参照する入力 run は
  保持本数に関わらず**削除しない**。
- 削除した run_id と解放バイト数を出力する。

## Non-scope

- `publish_run` の中で自動削除すること。公開は不変操作であり、副作用で他の run を
  消す経路を作らない（消す判断は別コマンドの責務）。
- 圧縮形式の変更（gzip 済み。次に進むなら Parquet で、sparse 化は検討しない）。
- `artifacts/` 以外（`.venv` / モデルキャッシュ等）の掃除。

## Done

- 保持本数を超えた状態で prune を実行し、古い run だけが消え、active release と
  その入力 run が残ることを実測で確認する。
- prune 後に `parts-search pipeline` が exit 0 で通る。

## Evidence

Level 2。実 `artifacts/` で保持本数を超えた probe を消し、既存 dataset が残ること、
および prune 後の `parts-search pipeline` が exit 0 であることを観測した。

## Verification

2026-09-29。

保持本数は `artifacts.retention.keep=2`。`runs=8`（1 pipeline の 7 本 + bootstrap）、
`models=4`（seed 3 + 1）。`publish_run` からは削除しない。

pin は `active.json` の release、rollback が戻る直前の 1 本、および manifest の
`path` / `artifact` + `manifest_checksum` で辿れる入力。`previous.previous` は pin しない。

実 `artifacts/`（prune 前 `du -sh` = 43M。完了 run は dataset 1、report 1。active.json は無い）へ
experiments を 3 本足して `parts-search prune` を実行した。

- 削除: `experiments/20200101T000000Z-prune00000000`（313 bytes）。`freed_bytes=313`
- 残した: より新しい probe 2 本、`datasets/20260924T150436Z-c5a3857d8d52`、`reports/20260924T150436Z-cd905b086054`
- 測定後、注入した probe 2 本は取り除いた。dataset と report はそのまま
- `judgments/.20260924T150437Z-2df57e0a0394-*`（失敗した公開の lock / staging）は対象外のまま残る

prune 後の pipeline は、既定 10,000 SKU ではなく文書どおり exit 0 になる 1,500 SKU / 700 family で実行した
（`/tmp/parts-search-prune-e2e`、約 11 分）。

```text
exit 0
golden_path_complete: true
quality: promote
blocked: []
failed: []
```

単体テストは `tests/test_prune.py`。`pytest` は git 未追跡の `prune.py` を
`test_every_source_file_is_tracked_by_git` が落とす。コミットすれば消える失敗で、テスト期待値は変えていない。

## Stop / Ask Owner If

- 参照関係の解析なしには「消してよい run」が決められないと分かったとき
  （manifest の入力 run_id を辿る実装が要るなら、範囲を owner へ戻す）。
